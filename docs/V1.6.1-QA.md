# v1.6.1 悬浮窗拖动验收

## 改动与回退基线

- 基线 `a50924a`，本地回退分支 `codex/rollback-v1.6.0`；本轮分支 `codex/v1.6.1-popup-drag`。
- 原实现虽有 `data-tauri-drag-region`，但 `core:window:default` 不包含 `allow-start-dragging`；补充独立 capability，范围仅限本地 `popup` 窗口。
- 唯一拖动元素为顶部中间空白区，避开标题、固定/关闭按钮、内容、底栏和边缘；拖动区保持普通箭头，按住左键移动即可，无固定等待时间。
- 不增加拖动轮询或覆盖全窗的鼠标捕获层，不改动原生缩放、尺寸限制和 450ms 去抖持久化。

## 验证

- 前端 36 项测试通过，含唯一空白拖动区域、交互按钮排除、最小权限范围以及原有朗读/菜单/历史回归。
- 8 组尺寸 × 浅色/深色布局通过；520×380、360×180 悬浮窗验证拖动区域有可用面积、上沿留出至少 6px、所有边/角不属于拖动区、普通箭头光标及原有菜单边界。
- 原生 Debug 使用全新 `QUICKTRANSLATE_QA_DIR`，未读取真实 API Key；截图检查独立拖动区和无底层外框。用户在原生验收中明确确认“拖动和缩放都正常”。
- 自动拖动测试的即时截图不足以可靠量化位移，因此不把它计为自动通过；原生交互结论依据用户实际操作确认。
- 尺寸保存、重开、非法尺寸限制及仅保存最后一次缩放修订由 Rust 回归测试覆盖；本轮未单独测量原生跨进程尺寸恢复。
- Rust 93 项通过、5 项环境依赖测试按原设置忽略；类型检查、格式检查、Clippy `-D warnings` 与前端/安装包构建通过。

- 本机生成签名安装包，校验版本、包签名及篡改拒绝；私钥不上传 GitHub。
