# v1.7.0 本机安装验收

2026-11-13，在 v1.7.0 公开发布之后进行。安装的是 Release 里的同一个安装包（SHA-256 `A5D8109543DB43DE82994539017618E37FF1D90717B8155473FBC88F517D0D26`），从 v1.6.2 覆盖安装。不公开用户的记录数量、内容、备份编号和凭据。

## 安装

- `scripts/install-local.ps1` 需要 PowerShell 7；这台机器只有 Windows PowerShell 5.1，脚本因无 BOM 的中文字符串解析失败。用内容相同、仅加了 BOM 的副本运行，没有改脚本逻辑。
- 脚本核对哈希，停止准确路径上的 1.6.2，备份程序、设置、窗口尺寸和两个数据库（含 WAL/SHM），写入 `COMPLETE.txt`，再静默覆盖安装并重新启动。
- 安装后运行中的程序路径不变，产品版本为 1.7.0。

## 数据保留

安装前用 SQLite 在线备份给两个数据库各做一份快照，安装并首次启动后再做一份，比较后删除了这些临时副本。

- 翻译历史：旧表里的记录全部拆入 `translation_history`，行数相同；按历史条目的全部列（编号、原文、语言方向、译文、释义、服务商、模型、创建和使用时间、收藏）逐行比较完全一致，完整性检查 `ok`。
- 生词本：`scripts/audit-vocabulary.py` 比较前后快照，词条、别名、复习事件、测试、生成缓存和规则完全一致。
- `settings.json`、`popup-window.json`、旧版迁移快照的 SHA-256 前后相同；OCR 插件目录的文件清单（相对路径、长度、SHA-256）前后相同。
- 凭据：只看凭据管理器里的条目名称，不读取内容。翻译、云端 OCR、云端朗读三个旧条目都还在；每个都新增了绑定到当前服务地址的条目和一个“已认领”标记。没有出现首次使用引导。

`scripts/audit-history.py` 在这次验收里报了“内容变化”：它用 `SELECT *` 比较拆分前后两张列不同的表，跨拆分必然不相等。已改为按历史条目的列比较；改后对升级前后的快照通过，对之后新增了记录的快照仍然报不一致。

## 真实快捷键

用脚本在新开的窗口里选中合成的英文句子，再注入真实的 `Alt+Q`（按住约 80 毫秒），截取应用自己的窗口。文本会发给已配置的翻译服务，用的是升级后认领的 Key。

| 场景 | 结果 |
| --- | --- |
| 记事本，全选 | 取到原文，译文正确，标题行显示 `划词翻译 · EN → 中文`；原剪贴板文本恢复 |
| 记事本，无选区 | 显示“未检测到选中文字”、当前快捷键和“手动输入”按钮 |
| Word 新建文档，选中一段 | 取到原文并译出；原剪贴板文本恢复 |
| Excel 新建工作簿，选中单个单元格 | 取到原文并译出；原剪贴板文本恢复 |

- 悬浮窗的尺寸是之前记住的大小；翻译进行中显示“正在翻译…”和“取消”；悬浮窗在前台时按 Esc 收起。
- 测试关闭了自己打开的记事本、Word 和 Excel，没有保存任何文档。

## 发现的问题

**应用启动后第一次按 `Alt+W`，选区遮罩出现几十毫秒就自己关闭；第二次及之后正常。** 重启应用复现了三次：第一次按键后遮罩在约 120–150 毫秒出现、30–80 毫秒后消失，或者没有被观察到；随后的按键遮罩立即出现并保持，Esc 可以关闭。

遮罩窗口在第一次按键时才创建。快捷键处理、遮罩的创建与显示、失焦即隐藏这几段代码自 v1.6.2 起没有改动，所以这很可能不是 1.7.0 引入的；没有在 1.6.2 上实测确认。推测是窗口刚创建时 WebView 初始化引起一次临时失焦，被当成了“离开遮罩”——悬浮窗在 1.6.2 修过同类问题，遮罩用的仍是旧逻辑。未修复。

## 没有验证

- 框选识别本身：没有拖动选区，没有向云端 OCR 上传任何图像。
- 朗读、历史页、生词本复习、设置页的保存与连接测试、手动输入、指定目标语言、术语表。
- 悬浮窗的拖动、边缘缩放、点击窗口外收起、固定。
- 长文本的流式显示过程和首段耗时；只看到短句在约 1 秒时仍在翻译、5 秒时已完成。
- 应用内更新路径（这次是本机脚本覆盖安装）、全新 Windows 用户环境、多显示器和其他缩放比例。
- 浏览器及其他程序里的取词、非 Alt 的自定义快捷键、原剪贴板为图片或富文本时的表现。
