# v1.7.2 本机安装验收

2026-11-16，在 v1.7.2 公开发布**之前**进行：先把签名好的安装包装到本机，用真实服务验收，通过后才发布。这一轮先后装过两个候选包，第一个在验收里暴露了两个问题，修复后重新构建的第二个就是最终发布的安装包（SHA-256 `1B430850A551DD4CE3597EDAD5F3A3C39CCC6C7E46C53B44C545CBDB13E75739`）。不公开用户的记录数量、内容、备份编号和凭据。

## 安装与数据

- 两次都用 `scripts/install-local.ps1` 加了 BOM 的副本从上一个已安装版本覆盖安装：脚本核对哈希，备份程序、设置、窗口尺寸和两个数据库并写入 `COMPLETE.txt`，再静默安装并启动。
- 安装后运行中的程序版本为 1.7.2；确认装上的程序里带有本版新增的提示文字，即确实是修复后的构建。
- 第一次安装前后用 SQLite 在线备份各做一份快照并比较，随后删除了临时副本：`scripts/audit-history.py` 和 `scripts/audit-vocabulary.py` 都报告内容一致。两次安装前后 `settings.json` 和 `popup-window.json` 的 SHA-256 都相同。

## 第一个候选包暴露的问题

1. **从悬浮窗打开的窗口是空白的。** 划词被服务拒绝后，点错误提示里的“打开设置”，弹出的设置窗口里什么都没有，界面树里只有一个空的 WebView 容器。在隔离调试构建里用“更多 → 打开生词本”复现了同样的现象。原因是这些命令是同步命令，在悬浮窗的 WebView 回调里新建窗口。改为异步命令后修复。
2. **服务的拒绝被显示成“API Key 无效”。** 当时保存的翻译模型是 `qwen-flash`，连续两次划词都被真实服务拒绝，悬浮窗显示“API Key 无效，请检查设置”。随后用户自己把模型换成了 `qwen3.8-flash`，同一个 Key 立刻可用，说明 Key 没有问题。当时返回的状态码和原文没有留下来，推断是该模型免费额度用完且开启了“免费额度用完即停”时的 403，没有得到证实。现在 403 不再一律说成 Key 无效。

## 最终安装包的验收

### 真实服务

用户保存的服务地址是阿里云百炼，翻译和云端 OCR 的模型都是 `qwen3.8-flash`（用户在验收期间自己改的）。以下请求都发给了真实服务，用的是用户保存的 Key；连接测试只在设置页的表单里临时改模型，没有保存，验收后保存的设置与之前相同。

| 项目 | 模型 | 结果 |
| --- | --- | --- |
| 真实 `Alt+Q` 划词（记事本里的合成英文） | `qwen3.8-flash` | 取到原文，译文正确 |
| 设置页“测试连接” | `qwen3.8-flash` | 连接成功 |
| 设置页“测试云端 OCR 连接” | `qwen3.8-flash` | 连接成功，识别用时 1033 ms |
| 设置页“测试云端 OCR 连接” | `qwen4-max` | 连接成功，识别用时 1849 ms |

`qwen4-max` 就是在 v1.7.1 上以“Parameter min_pixels must be greater than or equal to 4096”拒绝请求的模型。连接测试上传的是内置的小图片，不是屏幕内容。

### 从悬浮窗打开窗口

划词后在悬浮窗里点“更多 → 打开生词本”（这次运行里生词本窗口还没有打开过）：窗口里有完整的内容（界面树 70 个元素）。修复前同样的操作得到的是只有 1 个元素的空窗口。

### 截图遮罩

重启应用后注入真实的 `Alt+W`：第一次按键遮罩 146 毫秒出现，2.5 秒后仍显示并且是前台窗口，Esc 关闭；第二次按键立即出现并保持，另一个窗口到前台后收起。

### 图标

程序文件、设置窗口标题栏和托盘里显示的都是新图标。

## 没有验证

- 框选屏幕区域做真实的 OCR 识别：只做了连接测试，没有拖动选区。
- Claude：没有 Anthropic 的 Key，对 Claude 不发 `temperature` 这条规则仍然只有测试覆盖。
- 关闭“深度思考”带来的速度差别没有测量；只确认了带着这个开关的请求被 `qwen3.8-flash` 和 `qwen4-max` 接受。
- 模型拒绝附加参数后自动重试这条路径，在真实服务上没有被触发。
- “打开设置”“重新框选截图”在最终安装包上没有单独再点（前者的窗口当时已经从托盘打开过；两者与“打开生词本”是同一个改动，在隔离构建里验证过“重新框选截图”）。
- 403 的新提示在真实服务上没有出现过。
- 应用内更新路径、全新 Windows 用户环境，以及此前验收记录里列为未验证的其他内容。

## 测试留下的痕迹

- 翻译历史里多了测试用的合成句子。
- 第一次划词测试时剪贴板里不是文本，测试后留下的是测试句子，原内容没有恢复（原内容不是文本时应用不恢复）。
- 测试强制结束了自己打开的记事本，Windows 11 记事本下次打开时会恢复指向已删除临时文件的标签页，关闭即可。
